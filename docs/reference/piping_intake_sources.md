# What the piping parser actually reads

Derived by reading the code, not from what an IFC could ideally contain. Every claim below
carries a `file:line`. A datum with no line reference is not a requirement and does not appear
here.

The audit runs two parsers over the same file, and they are not interchangeable:

- **Path A** — `app/modules/ifc_reader/ifc_parser.py`, producing `ServiceElement`. This is what
  the five corrosion engines are fed through `phase_6c_corrosion_ui.py`. It carries the
  hydraulics (velocity, dead leg, temperature) and the declared second material.
- **Path B** — `app/modules/ifc_reader/piping_producer.py`, producing `PipingElement`. This is
  the network view used by the MM-001 and XM-001 comparators; it carries adjacency, environment
  class and the richer material resolution chain.

Both flatten every property set on the element into one dict, keying both the bare property name
and `"PsetName.PropertyName"` — `ifc_parser.py:400-418`, `piping_producer.py:1033-1053`. **The
authoring tool's choice of property-set name therefore does not matter to the parser**; only the
property name does. That is why the IDS names one property set per specification for definiteness
while the parser would accept any.

Engine codes: GC-001 galvanic, CC-001 crevice, MC-001 microbiological, MM-001 material-media,
XM-001 cross-material (`phase_6c_corrosion_ui.py:150-154`).

## Things deliberately not listed as requirements

- **`Pset_BimGuardCouple`, `Pset_BimGuardHydraulics`, `Pset_PipeSegmentOccurrence`** are written by
  this repo's own generator (`scripts/generate_demo_mep_model.py:56-60`, `:463-484`) and named in
  `docs/demo/RUNBOOK.md:181`. **No parser reads a property-set name** — both paths flatten and match
  on the bare property name (`ifc_parser.py:400-418`, `piping_producer.py:1033-1053`). The IDS names
  these sets because an IDS property facet requires one, not because the code demands them.
- **Storey elevation, IfcSpace boundaries, system flow direction, fluid chemistry, pipe schedule,
  IfcMaterialConstituent names** — no parser line reads them. They are not requirements.
