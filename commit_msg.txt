feat(shacl): wire up shacl opt-in pipeline and frontend preview panel

This change integrates the SHACL semantic validation engine into the core 
compliance pipeline as an opt-in side channel, aligning with the Execution 
and Validation Layer defined in the BIM-Guard Ontology Integration SRS. 
By introducing a non-authoritative `enable_shacl` flag, the procedural 
engines are left entirely unaffected while the frontend can now request 
and display raw RDF-based violations independently.

Key changes:
- `app/api/analyze.py` & `app/modules/contracts.py`: Added `enable_shacl` boolean to the `AnalysisRunRequest` and threaded it through the `run_analysis` API endpoints.
- `app/services/analysis_cache.py`: Included the `enable_shacl` flag within the `CacheKey` to prevent cross-contamination of cached procedural results.
- `app/services/analysis_runner.py`: Propagated `enable_shacl` down to the central orchestrator's compliance workflows.
- `frontend/src/lib/types.ts`: Synchronized `AnalysisResult` contract parity with the backend, adding `shacl_issues` and `shacl_error` properties.
- `frontend/src/lib/api.ts`: Updated the `getResults` API client to attach the `enable_shacl` HTTP query parameter dynamically.
- `frontend/src/routes/AnalyzeView.svelte`: Implemented a new UI checkbox to toggle the side-channel evaluation and introduced a dedicated, visually distinct SHACL Validation (Preview) panel for informational RDF violations.
